Invoice Control Agent

Supplier invoices arrive by email and get checked against each supplier's own contract — prices, payment terms, VAT, duplicates — before anyone looks at them.

Jeson Joshua · linkedin.com/in/jj-200987j

The idea

Invoice control is usually either a person reading PDFs, or a rules engine nobody can explain. This splits the work: the language model reads documents and explains what it found, deterministic code does every check and every calculation, and a person decides what to do about the exceptions.

Six steps, two kinds of intelligence.

  1. 01 An invoice arrives by emailReal input
    PDF or e-invoice XML, in whatever layout the supplier sends.
  2. 02 Power Automate saves every attachmentFlow
    Straight into OneDrive, timestamped, so a re-sent invoice becomes a new file the checks can catch rather than a silent overwrite.
  3. 03 Each PDF is read into structured dataAI
    Any layout, Danish or English, into a fixed schema. Net plus VAT must equal the total and the line items must equal the net, so a misread is caught instead of hidden.
  4. 04 Each supplier's MSA becomes exact rulesAI
    Agreed prices, payment terms, duplicate handling and scope, lifted out of the contract into a terms file the checks can read.
  5. 05 Every invoice is checked against its own contractRules
    Prices, payment terms, VAT, currency, duplicates, price changes, anomalies and scope. Each finding carries a severity and a recommended action; clean invoices are marked clean and left alone.
  6. 06 Ask in plain language, in Microsoft CopilotAI + code
    "Which suppliers make up 80% of our spend?" Asked in a Copilot Studio agent, which calls the Python engine through a secure custom API. The model chooses the analysis; Python computes every number and draws the chart. The answer shows the tools it called, so each figure traces back to source data.

The parts I cared about

  • No figure comes from the model. The model picks the analysis and writes the explanation. Every number is calculated in code from the source data. In finance that distinction is the whole thing.
  • Completeness is its own control. Emails received, files saved, invoices read, invoices in the agent — reconciled end to end on one page, so anything that fell out shows up the same day rather than at year end.
  • Only real exceptions surface. Severity and a recommended action on each one, exported as Excel and PDF. A list of everything is the same as no list.
  • Guardrails are explicit. Schema-enforced outputs, automated validation, and safeguards that stop the agent recommending an action the underlying contract terms do not support.
  • It meets people where they work. The same engine is exposed as an OpenAPI custom connector with an API key, so a Copilot Studio agent in Microsoft 365 gets exact totals, trends and Pareto analysis from code. Copilot handles the conversation; the numbers never come from the model.

Built with

Python Claude API Power Automate OneDrive / SharePoint Excel & PDF reporting Copilot Studio Custom API connector
